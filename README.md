# WLC

[中文](README-cn.md)

WLC validates Wirelink schemas and generates allocation-free C11 codecs,
a typed endpoint connected to the shared C kernel, or an owning C++20/Python UDP SDK.
Use WLC **0.13.0**, generated-code contract **0.13**, with matching Wirelink **0.13.0**.
Endpoint profiles use version **2**.

## Build and generate

From this repository, build a local compiler and put it on PATH:

```sh
cargo build --release --locked
export PATH="$PWD/target/release:$PATH"
wlc --version
wlc codegen-contract
wlc compile application.wl --out-dir generated-codec
wlc compile application.wl --profile application.bind.wl --out-dir generated-endpoint
wlc sdk application.wl --profile host.bind.wl --name application --out-dir sdk
```

The first two queries print `wlc 0.13.0` and `0.13`. The remaining commands
require your schema and profiles; use a dedicated output directory for each deployment.

- **Public codecs:** `.h`, `_values.h`, `.c` and a provenance manifest. Borrowed
  views cover the Schema-v1 value domain, including nested and repeated fields.
  Finite types also get owned values. These codecs depend on `wirelink/codec.h`.
- **Typed endpoint:** `_kernel.h/.c`, private RPC codecs, deployment/provenance
  manifests and, for a stream profile, its selected connector. Generated routes
  share the C kernel; the application supplies storage, time, owner execution and I/O.
- **SDK:** an installable C++20 client, Python sync/async package, generated C,
  CMake exports and wheel/sdist configuration. SDK profiles are bounded,
  RPC-only and `native_packet`; source builds need matching Wirelink with `cpp_host`.

## Select routes and transport

A profile refers to messages in your schema:

```text
profile version 2;
endpoint { envelope = native_packet; }
rpc Execute { request = ExecuteRequest; response = ExecuteResponse; }
send Sample { delivery = unreliable; }
direct Event { delivery = unreliable; }
```

Choose `native_packet`/NONE, `cobs_stream`/CRC16 or `bus_length16`/NONE explicitly.
Both RPC roles are enabled. Ordinary routes use Schema-v1 or explicit positional-v1;
RPC uses managed tagged bodies and instance/operation metadata.
Repeated borrowed fields are standalone-codec capabilities, not bounded kernel routes.

A successful admission snapshots input before return. Four outbound calls share
one owner with handlers and terminal callbacks. Queueing counts toward timeout;
response views last until callback return. Applications copy retained results and
own retry/idempotency and long-job protocols. See the [kernel execution model](https://github.com/starwey604/wirelink/blob/main/docs/kernel.md)
and [API reference](https://github.com/starwey604/wirelink/blob/main/docs/kernel-api.md).

```sh

cargo clippy --all-targets --all-features -- -D warnings
```

Generated bytes are deterministic. Keep generated files and provenance together;
wire conformance vectors, malformed-input tests and generated-C execution tests
establish behavior beyond output snapshots.
